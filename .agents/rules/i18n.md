# Textos e idiomas

La app usa `i18next` con `react-i18next`, y `expo-localization` para detectar el idioma del dispositivo.

## Estructura

```
src/lib/i18n/
├── index.ts          Configuración de i18next.
└── locales/
    ├── es.json
    └── en.json
```

## Reglas

- Ningún texto visible al usuario se escribe en el código. Esto incluye títulos, etiquetas, placeholders, mensajes de error, textos de accesibilidad y títulos de navegación.
- Los textos se obtienen con `useTranslation()` dentro de pantallas y componentes.
- Una clave nueva se agrega a todos los archivos de `locales/` en el mismo cambio.
- Las claves se agrupan por pantalla y usan camelCase: `signIn.title`, `petDetail.emptyState`.
- Lo compartido va en grupos comunes: `common.save`, `common.retry`, `validation.required`.
- Los valores variables se pasan por interpolación (`t('home.greeting', { name })`), no concatenando strings.
- Los plurales usan el mecanismo de plurales de i18next.
- Fechas, horas y números se formatean con `Intl` según el idioma activo, desde funciones de `src/utils/`.

## Componentes compartidos

Un componente de `src/components/` recibe sus textos ya traducidos por props. Los campos de `src/components/form/` son la excepción: traducen la clave del mensaje de error que les entrega el formulario.

## Qué no hacer

- No armar una clave de forma dinámica con strings que no se puedan rastrear en los JSON.
- No dejar una clave en un solo idioma.
- No traducir dentro de un hook de datos ni de un schema.
